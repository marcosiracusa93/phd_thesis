\chapter{Conclusions} \label{sec:conclusions}

This thesis demonstrates that DAE architectures can substantially accelerate irregular sparse workloads in scientific computing and machine learning without sacrificing programmability. The results lead to three main lessons about how future systems should support sparse tensor algebra.

\section{Lessons Learned} \label{sec:conclusions-lessons-learned}

The main lessons learned from this thesis are:
\begin{itemize}
    \item Traditional compute cores, which tightly couple memory access, control flow, and computation, cannot be scaled efficiently to support the irregular operations that dominate sparse tensor algebra. The two primary bottlenecks are \emph{sparse tensor traversal} and \emph{sparse tensor merging}. Sparse tensor traversal generates irregular memory accesses that require substantially more MLP than conventional cores can efficiently sustain. Sparse tensor merging introduces data-dependent control flow that defeats speculative mechanisms tuned for dense and regular workloads. Scaling conventional structures such as reorder buffers, load--store queues, and miss-status handling registers yields diminishing performance returns while incurring steep area and power costs. Therefore, sustaining full-core throughput is fundamentally impractical when memory access, control flow, and computation remain tightly coupled within the same compute pipeline.
    \item The right architectural boundary is to specialize sparse traversal, coordinate merging, and data marshaling while preserving general-purpose vector cores for arithmetic. General-purpose processors already provide many features that sparse tensor operations need: large memory capacity, flexible arithmetic, virtual memory, mature software support, and integration with real systems. However, they are inefficient at irregular sparse traversal and merging. DAE architectures expose a better split by separating memory access from computation into queue-connected units that can be optimized independently. By mapping traversal and merging to a specialized vector access unit such as the TMU, and computation to a general-purpose core, the system gains much of the efficiency of specialization without giving up flexibility, memory capacity, or software integration. The results also show that spatio-temporal locality is a key factor in determining the amount of memory-level parallelism, cache filtering, and specialization required by each workload.
    \item Efficient DAE architectures require automatic compilation, and that compilation is only practical with the right intermediate abstractions. The access unit and execute unit communicate through queues, so programmers must describe how data and control tokens are serialized, deserialized, and consumed across the access/execute boundary. This is difficult to write manually and also difficult to optimize automatically once the code has been fully decoupled, because explicit queue code loses much of the original control-flow and data-flow structure. Ember shows that the right compiler abstraction can overcome this challenge. With its SLC IR, Ember represents DAE code in a structured form that preserves control flow and data flow while exposing access streams, compute callbacks, and stream-to-value uses. This enables iterative DAE optimizations and allows automatically generated code to match the performance of hand-optimized implementations.
\end{itemize}

Together, these results show that sparse tensor algebra can be accelerated by specializing the irregular parts of the computation without replacing the whole processor or imposing a low-level DAE programming model on users.

\subsection{Follow-On Research Projects} \label{sec:follow-on-research-projects}
Beyond the thesis contributions themselves, this work catalyzed several follow-on projects:
\begin{itemize}
\item Francisco (Xicu) Marí Prats's master's thesis, \textit{Integrating the Tensor Marshaling Unit for Sparse Tensor Algebra with a RISC-V Processor}, presented the first RTL implementation and SoC integration of the Tensor Marshaling Unit (TMU)~\cite{mariprats2025mastersthesis}. The prototype integrated the TMU with a CVA6 RISC-V core in an OpenPiton-based system, demonstrated the feasibility of the TMU in a real SoC, and established the first milestone of a larger effort toward enabling the TMU in production systems.
\item Diego Gorfini's master's thesis builds on Xicu Marí Prats's first TMU SoC prototype by improving the communication path between the core and the TMU~\cite{mariprats2026bscsymposium}. This work integrates the decoupled SpMV access unit with Cohort's coherent shared-memory queues, avoiding memory-mapped I/O and ISA extensions. It also introduces a hybrid tile organization that co-locates the core, Cohort, and the TMU, allowing the accelerator to deliver operands directly into the tile's private L2 cache through a custom arbiter. RTL simulations show that this organization reduces inter-tile communication overhead and improves performance over the original multi-tile integration.
\item A collaboration between the Barcelona Supercomputing Center and UC Santa Barbara to improve OpenPiton as a research platform for accelerator integration, with a particular focus on supporting future TMU prototypes in many-core RISC-V systems.
\end{itemize}
