    \caption[Load-to-use latency of embedding lookups on CPU.]{Load-to-use latency of GNN embedding lookups on the multicore CPU baseline. Each subfigure reports one input graph, and each line corresponds to one embedding-vector size. The x-axis reports request latency normalized to the latency of an L1D cache access, while the y-axis reports the fraction of requests whose latency is higher than that threshold. High-locality inputs such as \texttt{proteins} drop quickly, indicating that most requests are served close to the core. Lower-locality inputs, especially \texttt{products} and \texttt{mag}, have much longer tails. The embedding-size lines capture spatial locality effects: larger vectors expose more contiguous accesses within each lookup, but also increase the cache footprint of each embedding vector, which can lengthen the tail when temporal locality is low. Across these temporal and spatial locality regimes, up to 86\% of requests take more than $10\times$ the L1D latency, and up to 36\% take more than $100\times$ the L1D latency. Thus, many GNN embedding lookups bypass the local cache hierarchy and become long-latency HBM accesses.}

    \caption[Architectural implications of embedding lookups on CPU.]{Architectural implications of long GNN embedding lookups on the multicore CPU baseline in \Cref{tab:embedding-cpu-system-specs}. Each subfigure reports one input graph, and bars correspond to different embedding-vector sizes. The left plot reports the average number of in-flight memory requests tracked by the core, the middle plot reports request-throughput utilization relative to the ideal rate of one request per cycle, and the right plot reports per-core HBM bandwidth utilization. Across all inputs and embedding sizes, request throughput remains low: the core issues requests at only 4\%--12\% of peak throughput, with an average of 6.3\%. This low throughput comes from memory-level parallelism requirements that exceed what the core can sustain, together with core-side inefficiencies such as data-dependent control overhead. Consequently, HBM bandwidth utilization remains low, ranging from 0.2\% to 2.4\% per core and averaging 1.6\%, even for \texttt{products} and \texttt{mag}, where most requests miss the caches and reach HBM. Thus, off-the-shelf CPU cores cannot generate enough concurrent long-latency requests to use memory bandwidth efficiently, motivating an architecture that tracks many outstanding requests outside scarce core resources.}
